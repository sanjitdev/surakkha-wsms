- (decision) aggregate model = hybrid [ADOPTED]. Observations (SensorReading, AnjaliReport, Complaint, LabResult, EnvSignal) are first-class events written to the stream before fusion. Incident is created lazily when fusion correlates ≥1 observation into a coherent story. After Incident creation, commands target the Incident aggregate (EscalateIncident, ExecutePlaybookStep, CaptureDeviation, ApprovePlaybookAmendment, IssueConsumerMessage). Pros: writes stay simple, reads stay focused, command boundaries clean. Cons: eventual-consistency reasoning between observation-time and incident-creation; spine must AD this.
- (decision) event-schema evolution = strict versioning + upcasters [ADOPTED]. Every event schema versioned (v1, v2, v3…). New versions add fields but never rename or remove. Old events upcasted on read by per-version upcaster functions. Projection rebuilds replay from genesis. Justification: audit chain is load-bearing (C-8 + C-13); history cannot be rewritten. Prevents event-schema drift between v1 and v2.
- (decision) projection consistency = live (sub-second lag in v1). Priya dashboard, PHA pane, fusion engine output read live projections. Simulator (FR-3.7) can opt into point-in-time replay against hypothetical playbook versions. Monthly review cluster (FR-3.6) reads live projection with bucketed materialization.

- (decision) RBAC enforcement = defense-in-depth, 3 layers [ADOPTED]. Permission checks at (1) gateway (admission), (2) service boundary (component-internal), (3) data-access layer (storage query). The auth service is a component; the policy matrix is per-city; the enforcement is a cross-cutting concern. Prevents the "single check is load-bearing" failure mode and makes audit-chain evidence of access policy violations complete.
- (decision) tenant isolation = strict logical per-tenant [ADOPTED]. Schema-level separation per tenant city; shared cluster; no cross-tenant reads at any layer. Matches C-1 + architecture-invariants.md §1. Federation (v2) operates on aggregated roll-ups only.
- (decision) data residency = in-region for Dhaka [ADOPTED]. All Dhaka-resident data lives in Bangladesh-resident storage. Cluster in Bangladesh region (AWS ap-southeast-1 candidate, or Bangladesh-region provider if available; deferred to stack selection). Aligns with C-10 + PRD §5.4.
- (decision) multi-radio contract enforced at gateway [ADOPTED]. Every sensor ingest request declares a radio tier (cellular/LPWAN/SD-card); the gateway routes through the right adapter. Adapters are port-swappable (C-15). Sensor silence beyond configurable threshold = audit event (per spec §3 of detection-layer.md).
- (decision) deployment topology = single-region Dhaka for v1 [ADOPTED]. Audit-chain gateway writes to local + single replicated peer. WB evidence export runs as scheduled job. Cheapest, matches "single city in v1" (NG-5). Multi-region is a v2-on upgrade when federation activates.
- (decision) observability = internal stack [ADOPTED]. Structured logs + metrics + traces; chain-integrity monitor (verify chain hash every N min); sensor-silence monitor (alert when any sensor silent > threshold); override-anomaly monitor (logged v1, enforced v2 per spec architecture-invariants.md §7). Vendor-neutral stack to fit WB procurement rules (no proprietary lock-in for an audit-chain-bound platform).
