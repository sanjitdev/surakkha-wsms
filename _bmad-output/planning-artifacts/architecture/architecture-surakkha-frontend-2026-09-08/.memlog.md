- (decision) AD-FE-1 — State management paradigm: useState + useEffect with shared hooks layer. Binds: no new state-management deps (no TanStack Query, no Zustand). Prevents: per-page duplication of fetch + polling + loading/error logic — every data fetch goes through a shared hook in web/src/hooks/ (useChain, useIncidents, useIncident, useSensors, useEvents). Rule: hooks own the useEffect + fetch + state transitions; pages only call the hooks. Same hooks work in mock and real-gateway modes (the fetch layer is the only thing that changes via VITE_USE_MOCKS).
- (decision) AD-FE-2 — Component composition boundary: prop-driven. Binds: 4-layer separation — (A) dim-4 primitives pure presentational; (B) page primitives compose A and accept plain props; (C) hooks own all data fetches and return shaped data; (D) pages are thin compositions of B + C. Prevents: primitives that self-fetch (mixing data + presentational concerns, harder to test); god-pages that own fetch logic inline. Rule: a primitive never calls a hook; a hook never imports a primitive; a page wires both and renders. NFR-FE1 (200-line cap) is enforceable only under this rule.
- (decision) AD-FE-3 — Mock/real transport boundary: network-layer. Hooks call fetch with relative /api paths; MSW intercepts at the service-worker layer; VITE_USE_MOCKS is the single swap point (no app code branches on it). Prevents: per-hook adapter patterns that would let some hooks bypass MSW; absolute URLs that escape the boundary; per-component conditional rendering keyed off mock mode. Rule: hooks MUST use relative /api/* URLs only; the only env var read at module load is VITE_USE_MOCKS.
- (question) REVIEWER-GATE finding: dim 5 §17.1 phrase "MSW + IndexedDB + useState+useEffect (no TanStack Query in v1)" already names the no-TanStack rule, but at least one parallel note in the codebase or design docs mentions TanStack Query as if it were an option. Conflict to surface, not silently override; for FE-1 the rule stands (AD-FE-1 binds).
- (decision) AD-FE-6 — Domain enum canonicalization at the hook boundary. Binds: every hook that returns a domain-shaped object (useIncidents, useIncident, useEvents, useSensors) and every page primitive that consumes it (InboxRow, KpiCard, FilterChip, AuditLogRow, JobRow). Prevents: casing drift on shared enums ('P1' vs 'p1', 'Onsite' vs 'onsite', 'Medium' vs 'medium', etc.); two consumers each deriving a different className or filter key from the same value. Rule: every domain enum key/value with more than one consumer is declared exactly once in `web/src/types/domain.ts` as a TypeScript `as const` enum; hooks return values from that enum verbatim (no `.toLowerCase()` at the boundary); primitive consumers apply `.toLowerCase()` only inside their own JSX class-mapping, never trust that the hook already lowercased it. Vitest check at `web/src/__checks__/enum-canonicalization.test.ts` greps for `as const` declarations and asserts each hook file imports from `./types/domain`.
- (decision) AD-FE-7 — Single-owner endpoint rule. Binds: every hook under `web/src/hooks/` and every page. Prevents: two hooks independently caching the same API endpoint with different refresh cadences, causing the UI to show two chain-freshness values side by side. Rule: an endpoint ↔ hook pair is declared exactly once in `web/src/hooks/_registry.ts`; pages compose hook returns, never fetch directly. Pages that need aggregate data call a hook that composes other hooks (e.g. `useDashboardView` calls `useChain` + `useIncidents` + `useSensors`); the registry lists which hooks compose which. Vitest check at `web/src/__checks__/endpoint-ownership.test.ts` parses every hook file and asserts its `fetch(...)` call's URL appears in the registry exactly once.
- (decision) AD-FE-8 — Session-state single-writer rule. Binds: every module that mutates the IndexedDB `session` row (login, logout, role-bounce defense-in-depth). Prevents: routes silently writing sessions behind the hook layer's back, so refresh-after-redirect misses a state change. Rule: only `web/src/hooks/useSessionRole.ts` and `web/src/mocks/idb.ts::loginAs()` / `logout()` write to the `session` row; route elements and pages call the hook or the IDB helper, never open idb-keyval directly. Vitest check at `web/src/__checks__/session-writer.test.ts` greps for `idbKeyval` usage outside the two allowed paths.
- (decision) AD-FE-9 — Layer-boundary enforcement. Binds: every `.tsx` and `.ts` file in `web/src/`. Prevents: barrel-file leaks (`components/ui/index.ts` re-exports a primitive that a hook imports, side-stepping AD-FE-2); deep relative imports that cross layers (`hooks/useEvents.ts` importing `components/layout/EmptyState`); IDE refactors that silently break the dependency direction. Rule: barrel files (`index.ts`) are forbidden inside `web/src/components/` and `web/src/hooks/`. Layer boundaries are enforced by import paths alone: A imports only from `web/mockups/theme*.css`; B imports only from `../ui/*` and `../layout/*`; C imports nothing from `web/src/components/`; D imports only from `../components/{ui,layout,pages}/*` and `../hooks/*`. Vitest check at `web/src/__checks__/layer-boundaries.test.ts` parses every source file's import map and asserts no boundary violation.
