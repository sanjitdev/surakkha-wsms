§3 — Universal envelope

Every chain write — over every transport — carries the same EnvelopeBase. The gateway does not parse past event_type until the typed payload matches.

EnvelopeBase · TypeScript
The 10 mandatory fields. All chain events use this shape.
interface EnvelopeBase { schema_version: number; // v1 = 1; bumped per AD-4 tenant_id: string; // 'dhaka' for v1 event_type: EventType; // see §4 for the closed enum event_id: ULID; // client-minted; AD-14 idempotency primitive occurred_at: ISOTimestamp; // source-side time ingested_at: ISOTimestamp; // gateway-set on accept actor_identity: ActorIdentity; // {role, ref, display?} correlation_id: ULID | null; causation_id: ULID | null; payload: EventPayload; // discriminated union on event_type }
Sample JSON · SensorReadingSubmitted
A sensor reading at pump station W with multi-radio cellular tier.
{ "schema_version": 1, "tenant_id": "dhaka", "event_type": "SensorReadingSubmitted", "event_id": "01J0A0A0A0A0A0A0A0A0A0A0A0", "occurred_at": "2026-09-07T10:00:00.000Z", "ingested_at": "2026-09-07T10:00:00.318Z", "actor_identity": { "role": "system", "ref": "01J0SENSOR00000000000000001", "display": "pump-station-W / cellular" }, "correlation_id": "01J0A0A0A0A0A0A0A0A0A0A0C00", "causation_id": null, "payload": { "sensor_id": "S1", "ward_id": "W7", "readings": { "turbidity_ntu": 6.8, "ph": 7.2, "chlorine_ppm": 0.4, "temperature_c": 28.4 }, "radio_tier": "cellular", "battery_pct": 87, "flags": ["spike"] } }
Ingested_at is server-minted. The client never sets ingested_at — the gateway sets it on accept, before the row hits the chain. This prevents client-side clock skew from corrupting replay analytics. The 318ms gap above represents typical cellular RTT for that sensor.

§2.5 — Actor identity (closed enum, AD-12)

Eight roles, frozen 2026-09-07. The ref field is always a session-bound ULID; the gateway rejects non-resolvable refs.

{ "role": "pha_approver", "ref": "01J0PHA00000000000000001", // session-bound ULID "display": "Dr. Mensah · DHAKA-PHA" // optional human-readable }
Single-character role enum expansion is structurally forbidden. A future "PHA_TEMP_REPLACEMENT" or "VENDOR_READONLY" is not a string append — it is an AD-12 amendment. Bumping the enum is a dual-signed SchemaVersionBumped event (AD-15).

§5.1 — HTTP POST /v1/chain (canonical write)

All chain writes go through one HTTP endpoint. The gateway enforces idempotency by (tenant_id, event_id) via SQLite uniqueness.

Request
Single Content-Type. Idempotency-Key header is the event_id ULID.
POST /v1/chain HTTP/1.1 Host: gateway.surakkha.bd Content-Type: application/json Authorization: Bearer <session_token> Idempotency-Key: 01J0A0A0A0A0A0A0A0A0A0A0A0 <request body = EnvelopeBase>
Response · 201 Created
Chain head advanced. Body returns the block hash anchors.
201 Created Content-Type: application/json { "block_hash": "0x7f3a9c2b4a8d6e1f0c5b9a7d3e2f8c4b1a6d9e0f2c5b3a8d7e1f4c9b6a2d", "prev_block_hash": "0x4e8d2c1f9a3b7e6d0c5f8a2b1d4e9c0f7a3b6d2e8c5f1a4b9d0e2c7f3a6b8d", "event_id": "01J0A0A0A0A0A0A0A0A0A0A0A0" }

§5.3 — HTTP GET /v1/chain (poll fallback)

When SSE has fallen back (per dim 5d §F state machine), every surface polls. Default cadence 30 s ± 10% jitter.

GET /v1/chain?cursor=01J0A0A0A0A0A0A0A0A0A0A0A0&limit=50 HTTP/1.1 Host: gateway.surakkha.bd Authorization: Bearer <session_token> Response: 200 OK { "events": [<EnvelopeBase>, ...], "next_cursor": "01J0A0A0A0A0A0A0A0A0A0A0F00", "chain_head_event_id": "01J0A0A0A0A0A0A0A0A0A0A0F01", "chain_head_hash": "0x7f3a·b9c2·4e8d·…", "projection_lag_ms": 312 }
Cursor is strictly greater-than. Server returns events whose event_id lexicographically exceeds the cursor. ULID time-ordering means cursor-based paging is also time-ordered. limit default 50, max 200.

Polling jitter math

const refreshIntervalMs = 30000; // default cadence const jitter = 0.9 + Math.random() * 0.2; // ±10% defeats thundering herd const actualInterval = refreshIntervalMs * jitter;

§5.2 — SSE /v1/stream (live push)

One-way gateway → client. Browser-native EventSource handles reconnection. Heartbeat every 30 s carries chain_head.

§6 — Chain reference format

Content-addressed by one sha256. No merkle root. UI truncates to 4×3 + ellipsis; chain stores the full 64 hex chars.

block_hash = sha256( canonical_json({ prev_block_hash, tenant_id, schema_version, event_type, event_id, occurred_at, ingested_at, actor_identity, payload }) ) // canonical_json = sorted-keys, no whitespace, stable UTF-8 // machine form: "0x" + 64 lowercase hex chars // UI form: "0x7f3a · b9c2 · 4e8d · ac12" (truncated visual) // full form: "0x7f3a9c2b4a8d6e1f0c5b9a7d3e2f8c4b1a6d9e0f2c5b3a8d7e1f4c9b6a2d"
Display rule. chain_ref always renders in mono (--family-mono) and is color-independent. Hover-to-reveal / long-press exposes the full 64 hex chars. UI truncation is a rendering choice, not a storage choice.

§7 — Dual-signature wire flow (AD-11)

Three events on the wire for every dual-sig command. The gateway rejects the underlying command if either SignatureAttestation is missing or the triple mismatches.

Step 1 · PHA attest
event_type: SignatureAttestation · role: pha_approver
{ "event_type": "SignatureAttestation", "event_id": "01J0P...PHA1", "actor_identity": { "role": "pha_approver", "ref": "01J0PHA..." }, "payload": { "attestation_target_event_id": "01J0P...TARGET", "attestation_target_payload_hash": "0xabc...", "attestation_target_version_id": "01J0P...V3.3", "attestation_kind": "pha_approver", "signature_algorithm": "ed25519", "signature": "0xd4f..." } } // → 201
Step 2 · utility_message_desk co-attest
Same (event_id, payload_hash, version_id) triple as Step 1.
{ "event_type": "SignatureAttestation", "event_id": "01J0P...UMD1", "actor_identity": { "role": "utility_message_desk", "ref": "01J0UMD..." }, "payload": { "attestation_target_event_id": "01J0P...TARGET", // SAME "attestation_target_payload_hash": "0xabc...", // SAME "attestation_target_version_id": "01J0P...V3.3", // SAME "attestation_kind": "utility_message_desk", "signature_algorithm": "ed25519", "signature": "0x8a3..." } } // → 201
Step 3 · Underlying command (PublicNoticeIssued)
Gateway verifies both attestations are on-chain with matching triples.
{ "event_type": "PublicNoticeIssued", "event_id": "01J0P...TARGET", "payload": { "attestation_event_ids": ["01J0P...PHA1", "01J0P...UMD1"], "notice_id": "01J0P...NOTICE", "template_id": "boil_v1_bn", "locale": "bn", "recipient_ward_ids": ["W7"], "body_hash": "0xabc...", "character_count": 68, "character_budget_alphabet": "ucs2", "verification_horizon_at": "2026-09-07T18:00:00.000Z", "zone_label": "Ward 7", "issuing_authority": "Dhaka PHA" } } // → 201 (both attestations already on chain with matching triple)
Failure mode · Triple mismatch
Step 3 lands against a typo-correction v2. Gateway rejects at write-time.
422 Unprocessable Entity { "rejection_reason": "attestation_triple_mismatch", "rejection_evidence": "Step-1 attestation references payload_hash 0xabc..., but current issuance payload hashes to 0xdef..." } // A SECOND CommandRejected event is written for traceability // NO chain event for the underlying command is written (per AD-11 tightened)
No buffered admission window. Both attestations must already be on the chain at write-time of the underlying command. There is no "wait 5 minutes" or "post-hoc admission" path. A half-attested issuance attempt produces a typed CommandRejected{reason: dual_signature_missing} event and no chain event for the underlying command is written (per AD-11 post-review tightening).

§5.5 — IndexedDB offline queue (Anjali-mobile)

Anjali's phone has unreliable network. The client mints event_id at user-acknowledged submit time; re-tries reuse the same event_id. Idempotency survives disconnect.

interface PendingEventRecord { event_id: ULID; // primary key, generated at submit envelope: EnvelopeBase; // serialized JSON submit_attempt_count: number; last_attempt_at: ISOTimestamp | null; last_response_code: number | null; chain_ref: ULID | null; // populated on 201 failure_reason: CommandRejected['rejection_reason'] | null; }

Sync algorithm (7 steps)

  1. App startup → scan pending-events where chain_ref is null AND submit_attempt_count < 8.
  2. POST each to /v1/chain.
  3. On 201: set chain_ref, decrement "queued" badge.
  4. On 409 DuplicateEventRejected: set chain_ref (it landed earlier); no retry.
  5. On 4xx other: increment attempt count; pause until exponential backoff (3s, 6s, 12s, …, 30m cap).
  6. On 5xx / network error: same backoff.
  7. After 8 attempts: surface SubmissionFailed{Permanent} toast; queue persists for human review.

§4.10 — CommandRejected catalogue (errors-are-events)

Every reject emits a typed chain event with a plain-English reason. Operators see the chain-reference ID — never raw JSON (per EXPERIENCE.md §"Error state").

missing_tenant_id
Request body missing tenant_id. Gateway rejects before any chain work.
missing_actor_identity
No actor_identity field. Session token not resolved.
role_not_in_enum
role outside the 8-entry AD-12 closed enum.
actor_ref_not_session_bound
ref did not resolve to a live auth-session reference. Token expired or forged.
duplicate_event_id
(tenant_id, event_id) pair already on chain. AD-14 idempotency trip.
cross_tenant_attempt
Session scoped to one tenant attempted cross-tenant read/write.
attestation_triple_mismatch
AD-11 invariant: payload_hash or version_id differs between attestations.
dual_signature_missing
Underlying command landed but one or both SignatureAttestation events are not on chain.
character_budget_exceeded
Filled template exceeds EN ≤160 GSM-7 or BN ≤70 UCS-2.
public_notice_rate_limit_exceeded
5/hr/actor issuance rate hit. Retry-After header present.
shift_coverage_missing_or_expired
utility_operator tried to issue without an active ShiftCoverageActivated.
retraction_target_not_on_chain
PublicNoticeRetracted referenced an event_id that does not exist on the chain.
malformed_payload
Payload failed discriminated-union match for the declared event_type.
unknown_event_type
event_type string not in the 29-entry closed enum.
schema_version_unsupported
schema_version higher than the gateway's current max version.

§13.1 — Monitor-emitted events

Chain-integrity failures are themselves chain events. The chain self-monitors; subsequent writes continue.

// ChainVerificationFailed — emitted by chain_integrity_monitor every 60s { "event_type": "ChainVerificationFailed", "actor_identity": { "role": "system", "ref": "01J0MONITOR0001" }, "payload": { "tenant_id": "dhaka", "failed_at_block_id": "01J0A0A0A0A0A0A0A0A0A0A0C99", "expected_hash": "0xabc...", "computed_hash": "0xdef...", "recompute_strategy": "forward_from_genesis", "monitor_actor_ref": "01J0MONITOR0001" } } // Note: a high-severity alert also logs at ERROR level (per spec-1-1 §I/O matrix)
CouncillorBypassActivated has two sole-emitters. The gateway SLA monitor (for sla_breach / quality_flag) or a PHA-pane pha_approver (for manual). No third emitter is permitted; the gateway rejects unauthorized emitters.
