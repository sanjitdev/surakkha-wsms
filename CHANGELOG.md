## [Unreleased]

### Changed

- Migrated OperatorDashboard (7 tables across 3 layouts), InboxList (action queue), and AuditLog (events) from hand-rolled `<table className="data-table">` markup to the shipped `<Table>` primitive. Gains: column sort (AuditLog `event_type` + `occurred_at`), column resize, tri-state select-all (InboxList), built-in loading skeleton + empty-state. No visual or behavioural changes to non-table portions of each page (KPIs, tabs, charts, filters, bulk-bar, copy buttons). All existing testIds preserved (`audit-row-*`, `audit-copy-*`, `inbox-row-*`, `inbox-row-check-*`) so Playwright selectors + existing test files continue to work.

### Added

- **FE-B5b-sort-a11y:** Resizable columns now respond to ArrowLeft / ArrowRight (±8px; Shift = ±32px) when the column header is focused (B5b-4). Min width 48px enforced.

- **FE-B5c:** DatePicker primitive (`web/src/components/ui/DatePicker.tsx`) + range sibling (`web/src/components/ui/DateRangePicker.tsx`) — Layer-A primitives implementing the WAI-ARIA grid pattern (`role="grid"` + 6×7 `role="gridcell"` per month). Single mode `value: Date | null` + range mode `value: { from, to } | null` kept as separate exports so each file stays under the AD-FE-5 ceiling and the two state shapes don't conflate. Locale-aware headers via `Intl.DateTimeFormat(locale, { month: 'long', year: 'numeric' })` + `{ weekday: 'short' }` — Bangla month + weekday names come free from the `bn` locale, no `date-fns` needed. Keyboard nav: Arrow keys move focus, PageUp/Down moves months (Shift = year), Home/End jumps to week endpoints, Enter/Space selects, Escape closes the popover and returns focus to the trigger. Click-outside closes (matches B5a's deferred decision — no auto-focus restore on outside click). Composed of 4 small files per AD-FE-5 ceiling: `useCalendar.ts` (~80 LoC, visible-month state + 6 helpers + min/max guard + `Intl` formatters; **zero third-party deps**); `Calendar.tsx` (~150 LoC, the DOM surface + ARIA + keyboard handlers); `DatePicker.tsx` (~110 LoC, single-mode composition root with click-outside + escape effect); `DateRangePicker.tsx` (~80 LoC, 2-step selection state — `pending: Date | null` tracks the first click and finalises `from`+`to` on the second). Styleguide Section 11 ("DatePicker") inserts 5 examples between Section 10 (Table) and the footer: (1) single with today as default; (2) range with last-7-days default; (3) single with `min=today` + `max=+30d`; (4) disabled state; (5) locale-toggle live readout wired to `useState`. New token-only stylesheet `web/src/styles/datepicker.css` (~120 LoC, mirrors `dropdown.css:42-67` + the 767px mobile floor → popover becomes a bottom sheet). 12 new i18n keys under `datepicker.*` in both `en/common.json` + `bn/common.json` (Bengali translations for all 12 keys). Styleguide extended with `.section--datepicker` + `.sg-datepicker-readout` (token-only). **Zero new third-party deps** — the planned `date-fns@^4` was dropped in favour of native `Date` + `Intl.DateTimeFormat`, matching the codebase's existing StyleguidePage pattern. Consumer migration to `Settings` / `VerifyFlow` / `AuditLog` is a follow-up (B5d).

- **FE-B5a:** Dropdown primitive (`web/src/components/ui/Dropdown.tsx`) — Layer-A combobox implementing the [W3C ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) with listbox autocomplete. Generic `Dropdown<T>` over `DropdownOption<T> = { value, label, disabled? }`. Two modes via `DropdownMode = 'single' | 'multi'` (declared once in `web/src/types/domain.ts` per AD-FE-6): single mode fires `onChange(value | null)`, multi mode fires `onChange(values[])` and renders chips with × inside the trigger. Searchable mode adds a filter input that narrows options by case-insensitive prefix match. Full keyboard nav: ArrowUp/Down moves the active descendant, Home/End jumps to first/last, Enter selects, Escape closes, type-ahead on the trigger. ARIA: trigger `role="combobox"` + `aria-expanded`/`aria-controls`/`aria-activedescendant`; popover `role="listbox"`; options `role="option"` + `aria-selected` + `aria-disabled` (multi `aria-multiselectable`). Styleguide Section 9 ("Dropdown") adds 5 examples — small list, searchable, disabled, multi pre-selected, and a wired live readout driven by `useState`. Styleguide extended with `.section--dropdown` + `.sg-dropdown-readout` (token-only). New tokens-only stylesheet `web/src/styles/dropdown.css` (~150 lines; mobile floor at `@media (max-width: 767px)` collapses the popover to a bottom sheet).

- **FE-B5b:** Table primitive (`web/src/components/ui/Table.tsx`) — Layer-A generic `Table<T>` over a row record type. Built from scratch (no `@tanstack/react-table`). Column descriptor `TableColumn<T> = { key, header, render?, sortable?, width?, align?, resizable?, className? }` lives in `web/src/components/ui/Table.types.ts`. Empty slot composes `<EmptyState>` (Layer-A); loading state renders 5 skeleton rows (`<span className="table__skeleton" />`). Pagination decoupled as `web/src/components/ui/Pagination.tsx` — prev/next `<Button>` + page chips + page-size `<Dropdown mode="single">` composed from B5a, with default options `[10, 25, 50, 100]`. Zero new third-party deps; no barrel files; no edits to `OperatorDashboard.tsx` / `InboxList.tsx` / `AuditLog.tsx` / `InboxRail.tsx` (B5d migration is the follow-up).

### Fixed

- **FE-B5b-sort-a11y:** Table sort comparator now treats nulls as LAST (was first; B5b-1); Date values now compare chronologically (was locale-string; B5b-1). Resize listeners now cleaned up on unmount mid-drag (B5b-2; was leaking). Select-all checkbox now tri-state with `indeterminate` + `aria-checked='mixed'` for partial selections (B5b-3).

- **FE-B5a-flip:** Dropdown popover now flips above the trigger when there isn't 240px + 16px of room below the viewport edge (B5a-1 — viewport-collision auto-flip). `useDropdownState` measures `triggerRef.current?.getBoundingClientRect()` + `window.innerHeight` in a `useLayoutEffect` (synchronous before paint, SSR-safe via `typeof window` guard, jsdom test-safe via `Object.defineProperty(window, 'innerHeight', ...)` + `Element.prototype.getBoundingClientRect` mock) and toggles a `placement: 'below' | 'above'` state. CSS keys off `[data-placement='above']` to anchor the popover above the trigger with the same `--space-sm` offset. Mobile bottom-sheet behavior unchanged — `@media (max-width: 767px)` already forces `position: fixed; bottom: 0` and wins on specificity. No third-party deps; no public API change.

- **FE-B5a-keyboard:** Dropdown type-ahead now cycles within a same-letter match group (typing `a` twice with `[Apple, Apricot, Avocado]` advances Apple → Apricot → Avocado → Apple; previously stuck on first match). 1-char buffer tracks the last typed letter within the popover session; repeated presses of the same letter cycle, different letters extend the prefix (multi-char `ap` match). Buffer resets on Escape, outside-click, and `close()` via a `typeAheadBufferRef` shared between `useDropdownKeyboard` and `useDropdownState`. Disabled options skipped; no public API change.

- **FE-B5a-harden:** Dropdown primitive a11y hardening — outside-click now restores focus to the trigger button (B5a-3); trigger `aria-controls` now references the search input id (space-separated alongside the listbox id) when `searchable={true}` (B5a-2). Both fixes bring the Dropdown to WAI-ARIA combobox compliance; keyboard users previously lost focus to `document.body` on click-outside, and SR users previously heard "controls listbox" but not the second interactive element in the combobox subtree.

- **FE-1.5b review-loop D1:** `InboxList.tsx` — removed the duplicate `<span className="inbox-bulkbar__count">` copy-paste leftover from the FE-1.5b ship (lines 294-296 rendered the same `<strong>{selectedRows.size}</strong> selected` twice). The new `fe-1-5b-inboxlist.test.tsx` structural assertion `expect(bulkbar?.querySelectorAll('strong').length).toBe(1)` locks this fix.

- **FE-1.5:** AuditLog / InboxDetail — the `ChainEvent.actor_identity` field is a `{kind, ref, display}` object (per dim 7 §2.5), not a string. Both pages now render `actor_identity?.display ?? '—'` instead of crashing with "Objects are not valid as a React child".

- **FE-B5d:** Bangla locale propagates to date/time renderers — 8 sites previously hardcoded `toLocaleTimeString('en-GB', …)` / `toLocaleDateString('en-GB', …)`, so Bangla users saw English timestamps. Now wired through `useDateFormatter` which reads `useLocale()`.
